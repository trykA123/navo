# Beta battle plan · v0.9

Status: running (B1 waits for B0; B2 done; B3–B5 atomised, partly done; B6 planned in `plans/2026-10-27-tiling.md`; B7 and B8 atomised from the D82 picks; Q1–Q3, Q5–Q20 open, architect defaults apply until answered) · Repo: `navo` · Branch: `beta-bN-<atom>` per atom · Started: 2026-10-27

## Goal

Navo becomes safe, configurable and pleasant for daily work on Windows. A mistaken Shift+Del or overwrite can be undone for days. The window works at any width. Automotive and embedded files open in calm, rich viewers. Workspaces, tiled panes, find files and a preview pane make daily work faster. Modules, themes and keys become the user's choice. Each milestone below ships on its own as a GitHub pre-release.

Sources: roadmap "Right after the alpha" and "v1 Beta"; D13, D14, D16, D21, D58, D65, D68, D72–D82; P38 A5/A6; P43; `docs/retention.md` and the plans on `backend/beta-retention-on-main`.

## What exists today (checked at `6873ea06` and `backend/beta-retention-on-main` at `670250a5`)

- **Retention engine, not yet on main.** `navo-retention` (capture, restore, purge, reconcile, adopt, bounded maintenance), `navo-store::RetentionCatalog` (schema V7, `list_after` paging) and `[retention]` settings (`retain-deletes`, `retain-overwrites`, `days`, `max-volume-mib`, `min-free-mib`; both flags default `false`). Everything runs only with `--experimental-retention` (`navo-app/src/cli.rs:80`, `gui.rs:338-346`). Missing for users: activation, settings UI, Recently deleted, Ctrl+Z restore, periodic maintenance, terminal metadata pruning, native Windows runtime checks. Containers still use `.navo-retained-*` names.
- **Undo** exists for rename jobs only: `UndoOffer` (`navo-ui/src/browser/rename_batch/hooks.rs:10`) and `window_view/undo.rs`.
- **Fonts.** `navo-ui/fonts/` bundles Archivo and JetBrains Mono. `tokens/design_b.rs` sets `ui_font` and `numbers_font` to Archivo. Inter and Space Grotesk are not bundled. The `appearance.font` and `appearance.font-size` settings exist (default Inter, 13) but nothing applies them.
- **Layout.** Two panes in one `Splitter` (`window_view/layout.rs`). No minimum window size (`title_bar/mod.rs:37`). Header and row cells compute widths in separate code (`file_list/header.rs`, `file_list/row.rs`). `ListParts` hides columns only by user choice. Tabs never overflow (`primitives/tabs.rs`). `test_window::open_sized` already opens a test window at a given width.
- **Settings sheet** is hand-written: `Section` and `Field` enums and four `FieldSpec` tables (`navo-ui/src/settings/fields.rs`). No module schemas. `navo-plugins` is an empty crate.
- **Shortcuts.** A user keymap with live reload and a Shortcuts page exist (`window_view/user_keymap.rs`, `settings_sheet/shortcuts.rs`, P20 done).
- **Automotive.** DBC and A2L files open in F3 as one flat table of description rows (`navo-ui/src/window_view/viewer/kinds/description.rs:115-144`, checked at `c016ee35`); D82 replaces it with an outline and an inspector (B3 V7a–V7k). Rich ELF/MAP is merged; CSV and CAN trace column resizing (P38 A5/A6) is not.
- **Background work.** P43 is written and its Q1–Q3 were accepted; only J0 ran. `IoQueue` never classifies a volume.
- **Not present:** workspaces, refresh mode per location, module registry, safe mode, ignore list, copy rules, custom colour or icon themes, soak test, spreadsheet viewer, NSIS installer.

## Decisions

Final for this plan. A worker that finds one wrong stops and reports.

- D1 — **Milestone = pre-release.** Each milestone merges as squash commits, passes the full gate and Windows CI, and the `deployer` publishes a pre-release `beta-<date>` with the exe and zip. The owner checks it on a Windows PC before the next milestone's last atom merges.
- D2 — **Retention is on for everyone.** The `--experimental-retention` flag goes away. Coordinated mode (mutation leases, private-path protection) is the only mode. `--no-retention` starts without leases and without retaining, as a safe-mode escape; it keeps the reserved-folder protection (retention plan D4). One-instance requests must match, as today.
- D3 — **Volumes that cannot retain fall back openly.** When the target provider has no atomic rename or no file identity (network shares, some USB file systems), Shift+Del shows the ordinary permanent-delete confirmation with one more line: "This drive cannot keep deleted files." It never refuses and never retains silently.
- D4 — **Recently deleted is a side sheet** on the existing `side_sheet` (like Settings), opened by the command `files.recently-deleted` (Ctrl+K and the File menu). It lists retained entries newest first. Restore returns an entry to its original path; on a collision it keeps both with " (restored)" added. "Delete now" purges one entry after a confirmation. Its visual direction comes from designer round R1.
- D5 — **Ctrl+Z after a retained delete or overwrite restores it.** `UndoOffer` gains a kind: `Rename` (today) or `Retained(Vec<RetentionId>)`. The undo confirmation names the count and the folder, as rename undo does.
- D6 — **Maintenance runs on a timer, too.** Bounded maintenance runs once after start-up recovery and then every 6 hours, on a worker, holding the mutation lease, at most 32 purges per pass (the existing per-job bound).
- D7 — **Fonts (D78).** Inter for the interface and numbers (tabular numerals), JetBrains Mono for paths, viewers and hex, Space Grotesk SemiBold for the wordmark, window titles and sheet titles. Archivo is removed. Font files come from the official releases (Inter 4.1 `rsms/inter`, Space Grotesk 2.0.0 `floriankarsten/space-grotesk`), with their OFL licence files beside them. The `appearance.font` and `appearance.font-size` settings apply live.
- D8 — **Responsive layout (D80 1–6).** Minimum window size 480 × 360 px. Header and row cells take their widths from one function. Names end in an ellipsis; Ext, Size and Date are fixed width. Columns drop automatically in the order Ext, Date, Size when the pane is too narrow; this never changes the user's View setting. Below 900 px window width the window shows one pane (Q3). Tabs shrink to a minimum width, then the rest move into a "+N" overflow menu. Layout tests render at 480, 800 and 1280 px and run in the normal nextest step of the gate.
- D9 — **Tiling panes follow their own plan.** The owner picked direction D plus free layouts, user presets and Shift+drag swap (D82). `plans/2026-10-27-tiling.md` holds its decisions (TD1–TD14) and atoms (TL1–TL17).
- D10 — **Models (owner, 2026-10-26).** The main workforce is Codex Sol 6.1 through crew: api-builder and ui-builder at medium, high where the table says so; checker on Sol 6.1 high. Opus 5.5 medium for senior, designer and reviewer-senior. Sonnet 5.5 medium only for trivial edits (patcher) and the documenter. Haiku only for scout lookups. Never Opus high. The B1 and B2 rows were written before this rule; B1 atoms run on the new models. *Amended 2026-10-29:* Codex Sol 6.1 high is the standard Codex worker; DeepSeek V4.1 Flash (through dshw) may run pure-backend atoms (core, fs, store, index, app back ends, xtask), never an atom that touches `navo-ui`; Sonnet for light and UI work; Opus 5.5 medium for hard atoms.
- D12 — **Order (D81).** The owner's priority items come first, grouped as B3–B6. The items moved into the beta from v1.0 and later follow as B7–B9. Every other beta item comes after them (B10–B16), including background work and Raw/Pretty, which the roadmap listed "right after the alpha".
- D13 — **Open a terminal here is a core command now.** `files.open_terminal` starts the configured terminal in the active pane's folder. It moves behind the module registry when B12 lands. Network and archive folders refuse with a status line.
- D14 — **Workspaces belong to a window (Q9), shown as a tray (D82).** A window holds an ordered list of one to nine named workspaces; Alt+1…9 reach them by position. Each holds the layout with its ratios (tiling TD13), panes, tabs, history and the target pane, not listings. Alt+N makes a new one from the current layout. Switching keeps the workspace you leave exactly as you left it; its unsaved changes stay a draft until Ctrl+S saves them or Discard drops them (Q12). Saved states and drafts are kept in the session file. *Changed on 2026-10-27 with D82:* the first D14 had nine fixed slots, where an empty slot copied the layout and switching saved; the tray prototype the owner picked shows a list that grows with Alt+N and drafts.
- D15 — **Accessibility basics, scope.** Narrator reads the file list rows, dialogs and Ctrl+K results with a role and a name. Every focusable element shows a focus ring. Every animation honours reduced motion. Windows contrast themes switch Navo to the system colours. A UI scale setting (80–200 %) applies live.
- D16 — **DBC and A2L in F3: outline and inspector (D82, direction B).** The Rich view shows an outline on the left and an inspector on the right; Ctrl+B and Ctrl+I toggle them (D58). DBC outline: sender nodes → messages (ID, name, cycle) → signals (start|length, unit); messages without a known sender sit under "No sender". A2L outline: a module line, Characteristics grouped by kind (MAP, CURVE, VAL_BLK, VALUE, others), Measurements, Compu methods. The inspector shows the selected item: path crumbs, kind and name, problems, fact tiles; for DBC the bit layout, formula, receivers, value table and sibling signals (a selected message shows its bit layout and its signal list: the "signals in the middle" of D82, Q14); for A2L the limits, axes and compu method with "also used by", or a compu method's coefficients and users. Keys: / or Ctrl+F find, N and Shift+N next and previous hit, J/K or arrows move, Left/Right fold, B bookmark, Esc clears the find. Bookmarks save per file by source line. The flat table goes away.
- D17 — **Workspace tray (D82, direction D).** The status bar ends in a workspace button (grid icon, name, "2/4", "Draft · n"); clicking it pins the tray. Holding Alt in the file list shows the tray after the modifier-hints delay, above the hints drawer; Alt+n shows it at once and previews workspace n with the ribbon "Previewing <name> · release Alt to switch · Esc to stay"; releasing Alt switches. Each card shows a small layout preview with folder names, the number, the name, "open" for the current one, and Save and Discard when it has a draft, else rename, move left and right, and delete. Alt+N makes a new workspace. Alt+Shift+Left/Right reorder, because Alt+Left/Right stay Back and Forward (the prototype used Alt+Left/Right). Delete asks nothing; Ctrl+Z restores. The tray never appears inside a viewer, a dialog or Ctrl+K.
- D18 — **Inspector column (D82, direction A).** Ctrl+Q shows or hides a column right of the panes: preview on top, properties below. Ctrl+I folds the properties part; Alt+Enter moves focus into it. Width 360 px by default, 280–560 px by dragging, saved in settings. It follows the active pane's cursor and reuses the preview loaders and pools. Below 1200 px window width, Ctrl+Q opens today's preview side sheet instead (Q15). Ctrl+Shift+T switches the active pane to thumbnail rows. Properties: General, Dates, Attributes, Owner and permissions (read only), Hashes on demand (CRC32, MD5, SHA-256 with Copy). Edits (Q16) apply with Apply or Ctrl+Enter as one job with Ctrl+Z; Revert drops them; marked files show mixed values that stay untouched unless changed.
- D19 — **Find files in Ctrl+K (D82, direction A).** Ctrl+K gets four modes: Names (today), Content, Commands, Collections. Alt+F7 opens it in Content mode with the active pane's folder as scope. Words are the text; `ext:`, `size:`, `mod:`, `attr:`, `in:`, `arc:` and `re:` tokens are filters shown as chips; Alt+C toggles case, Alt+R regex. The palette previews the first hits; Enter opens a hit in F3 at its line. Ctrl+Enter in Content mode sends the search into a new tab of the active pane as a virtual folder (in Names mode Ctrl+Enter keeps "other pane"). The results tab streams hits with progress; Esc stops and keeps what was found. File rows carry their hit lines; F3, F5, F6, Space, F2 (rename) and drag act on the real files; copying asks whether to keep the folder structure. "Keep as collection" saves a saved search or a snapshot; "Add to collection" and Alt+Insert add files by hand; collections open as tabs with a From column. Details in B7 D19a–D19c.
- D11 — **Checks.** Workers run `cargo xtask check -p <crate>` and the nextest filter in their row. The full `cargo xtask gate` runs once per milestone on the merge branch. One cargo build at a time (nice 10, `CARGO_BUILD_JOBS=8`). Windows CI is the real gate (later also a Windows VM test agent); a Linux run is a quick filter.
- D20 — **Libraries (D88, 2026-10-29).** A library comes in only with its feature, pinned, after a short test or measurement shows it helps. GPL, AGPL and LGPL crates are never added. The agreed list is the library map in `plans/2026-10-28-speed.md`.

## BI · Index like Everything

D83: built before the other beta work. The service already reads the MFT and follows the USN journal, and it already saves a snapshot. The owner still saw two faults on a Windows PC (alpha-2026-10-27c): the app walked `C:\Users\…` again and again, and the service used about 235 MB. The walks came from the fallback when the service did not answer in time (fixed in `ef34edd6`: a silent service no longer starts a walk). The open question is why the service was silent at all.

### Components

- `navo-index` host, NTFS index and pipe server: answers, start-up and memory.
- `navo-app` search hooks: which roots the app ever walks.
- `navo-app` bench: the comparison command.

### IX8 · Updates in place (in-app updater)

Atomised 2026-11-02 (architect Elendil). Every atom is blocked until the orchestrator confirms. D22a–D22i are proposed; when accepted, `docs/decisions.md` gets one entry for them.

**What the user gets.** An installed Navo finds a new release by itself, downloads it quietly and becomes the new version the next time it starts. Settings → Help shows the state and has Check now. The index service follows in the same restart, with one UAC prompt only when the service itself changed. A portable copy never updates itself.

**What exists (checked at `0406552d`, paths under `crates/navo-app/src/`).**

- `velopack` =1.2.161 is already a dependency. `installer.rs:18-25` runs `VelopackApp::build()` with only the uninstall hook. Velopack's start-up auto-apply is on by default (`velopack-1.2.161/src/app.rs:30-56`): once a package is staged, every start applies it, also a second launch that only forwards to a running Navo.
- `release.yml:132-175` packs with `vpk` 1.2.161: pack id `NavoApp`, channel `win`, version `0.0.1-<alpha|beta>.<date><letter>`. Every release is a GitHub pre-release. Each carries `releases.win.json` with one Full package, its size, SHA-1 and SHA-256 (checked on `alpha-2026-11-02a`: 32.9 MB). No delta packages.
- The binary does not know its release: `navo --version` prints the Cargo version `0.0.1` (`main.rs:146`).
- `--index-service install` (elevated, `index_service/mod.rs:88-161`) copies the running exe to `C:\Program Files\Navo\Index`, re-registers and restarts the service with rollback, and removes the legacy Ferrite service. The pipe protocol has no version (`navo-index/src/pipe/frames.rs:51-110`).
- Settings → Help shows "Navo <version>" (`navo-ui/src/settings/help_page.rs:47-72`). Settings → Search shows the service state with Install and Remove (`navo-ui/src/settings/search_page.rs:13-40`).
- Navo runs one process per profile (`instance/naming.rs:6-15`); the windows of a profile share it.

**Velopack facts** (read in the crate source in the cargo registry, `velopack-1.2.161`). Verified on crates.io 2026-11-02: 1.2.161 is the newest stable version (MIT, 2026-09-29); 1.3.39-g8d2844f (2026-10-17) is a pre-release and stays out. `GithubSource::new(url, token, prerelease)` makes one API call (`api.github.com/repos/<repo>/releases?per_page=10`, 60 per hour per IP without a token), then fetches `releases.win.json` of each release from `github.com`; a feed that does not parse is skipped silently, so a set of bad feeds reads as `RemoteIsEmpty`. `UpdateManager::new` fails with `NotInstalled` without a Velopack manifest; `get_is_portable()` is true for the portable zip. `download_updates` takes a lock, writes `<name>.partial`, checks size and SHA-256 (SHA-1 when the feed has no SHA-256), then renames; the next download deletes old partial files. `HttpOptions.TimeoutMilliseconds` defaults to 0 (no timeout) and `GithubSource` cannot set it. TLS is `ureq` 3.5 with rustls and the bundled `webpki-roots`, not the Windows certificate store. `on_after_update_fast_callback` is killed after 15 s. **Unverified:** whether `Update.exe apply` closes or kills other running processes of the app; whether `ureq` refuses an https → http redirect.

**Appetite.** Four agent days, VM run and review included. Over that: cut IX8n (the ready notice) and IX8g (bump the revision by hand). Never cut the apply guard or the failure tests.

**Non-goals.** Delta packages. Channels or switching between alpha and beta. Rollback from the UI. Updating the portable zip or a bare `navo.exe`. Restarting Navo by itself. Metered-network detection. A signed feed (open question). Linux and macOS.

**Alternatives considered.**

- Velopack's default auto-apply at start: lost. It applies from a forwarding second launch while the first Navo runs.
- Apply at quit (`wait_exit_then_apply_updates` when the last window closes): lost. Quit stops jobs with a 10 s limit (`navo-ui/src/window_view/closing.rs:10`), a Navo kept in the tray rarely quits, and a Windows shutdown can cut the apply. At start nothing runs yet.
- `HttpSource` on `releases/latest/download`: lost. `latest` skips pre-releases, and every Navo release is one.
- An own GitHub client: lost. Velopack already stages, locks and checks size and SHA-256.
- The service update inside Velopack's after-update hook: lost. The hook dies after 15 s; a UAC prompt can wait longer.
- Service version = release version: lost. Every update would ask for UAC.

#### Decisions for IX8 (proposed)

- D22a — **Velopack against GitHub.** `UpdateManager` with `GithubSource::new("https://github.com/trykA123/navo", None, true)` and `UpdateOptions { AllowVersionDowngrade: false, .. }`. `velopack` stays =1.2.161 and `vpk` in `release.yml` stays the same version; they move together. The feed stays as `release.yml` writes it today.
- D22b — **Only an installed copy updates.** `Installed` (from Setup.exe) checks, downloads and applies. `Portable` (Velopack's portable zip) and `Unpackaged` (the bare `navo.exe` asset, a dev build, any `NotInstalled`) make no request, download nothing and apply nothing. Settings → Help says: "This copy does not update itself. Get the installer from GitHub."
- D22c — **When it checks.** With `updates.check` on (default), one check 10 s after the first window shows. Check now in Settings → Help works at any time, also with the setting off. A found release downloads at once in the background. One check or download runs at a time. A check gives up after 30 s.
- D22d — **Apply only at the next start.** `installer.rs` turns Velopack's start-up auto-apply off. A start that opens a window (`Command::Open`) applies a staged newer package before profile choice, instance start, recovery, retention maintenance or any window, and only when no other Navo process runs from this install's folder. Otherwise the package waits for a later start. Navo never restarts by itself. Command-line starts (`--index-service`, `--version`, helpers, Velopack hooks) never apply.
- D22e — **Service revision.** `SERVICE_REVISION: u32` in `navo-index` starts at 1. The service answers `VersionV1` with the revision and the build tag (`NAVO_BUILD`, else `dev`). A service that cannot answer is older. `cargo xtask service-revision` stores a hash of the service sources and fails when they change, until the developer runs `--bump` (users get the new service with one UAC prompt) or `--same`.
- D22f — **Service step.** After the first window shows, on a worker: when the app is `Installed`, the Navo Index service runs and its revision is lower than the app's (or unknown), Navo asks once for elevation and runs `--index-service install`. Same or higher revision: nothing. Declined or failed: `<data>/index-service-declined` keeps that revision, Navo does not ask again for it, and Settings → Search shows "Older than Navo" with Update. A portable copy only shows the status. Setup.exe over an older version takes the same path on its first start.
- D22g — **Quiet.** No dialog, badge or toast for updates. Settings → Help shows one line under the version: "Checking for updates…", "Navo is up to date", "Downloading Navo <version> (40 %)", "Navo <version> is ready. It updates when you next start Navo.", or a failure line. When a download finishes, one window shows the ready text once as a status notice. Fade only, about 80 ms.
- D22h — **Failures stay quiet.** Each failure gives one log line with its kind and one line in Settings → Help: offline "Could not reach GitHub"; rate-limited "GitHub asks Navo to wait. Next try after <time>" (1 h, also for Check now); bad feed "The update list could not be read"; interrupted "The download stopped. It starts again next time"; damaged "The download was damaged and was removed"; busy "Another Navo is updating". No dialog, no retry loop.
- D22i — **The service is its own exe (proposed, owner request 2026-11-02).** Today Task Manager shows the service as a second "navo.exe" (`C:\Program Files\Navo\Index\navo.exe --index-service run`), which looks like a stray Navo; a SYSTEM service cannot group under the user's app. The service becomes `navo-index.exe`, built from a new crate `navo-index-service` (library plus `[[bin]] navo-index`), with its own version resource (FileDescription and ProductName "Navo Index", the Navo icon, FileVersion and ProductVersion as the app's) and the service description "Keeps the file index for Navo search up to date." A new crate, not a second `[[bin]]` of `navo-app`: a bin there shares `navo-app`'s dependencies and `build.rs`, so it would carry the "Navo" resource and reach the service code only through `#[path]` tricks; the crate depends on `navo-index`, `navo-store`, `navo-fs`, `navo-core`, `navo-diag` and `windows-sys`, never on `navo-ui` or `gpui`. `navo-app` keeps the client side (query, elevation, install and remove commands) through the library. Install copies the `navo-index.exe` that sits next to `navo.exe`; without it, Install refuses with "navo-index.exe is missing next to navo.exe". The PDF helper stays a child of `navo.exe`.

#### Data safety, security and privacy

- **Feed trust.** The feed is not signed; Navo has no code signing yet (D73, D88). Trust rests on GitHub serving `trykA123/navo` over HTTPS, checked by rustls against the bundled Mozilla roots. Velopack checks each package's size and SHA-256 against the feed before staging it; a mismatch stages nothing and leaves the installed version as it is. The checksum protects the download, not a stolen GitHub account or release token.
- **HTTPS only.** The repository URL is a constant. No setting, file or environment variable changes it in a release build. The folder feed of IX8q exists only in `tester` builds; a test proves the release path never reads its variable. No token is ever sent.
- **No downgrade.** Velopack's downgrade option is off, and `navo-update` refuses an equal or older version by itself. A release removed from GitHub rolls nobody back.
- **No restart while work runs.** Navo never restarts by itself. Apply happens only at a start, before this process has windows, jobs, recovery or maintenance, and never while another Navo process from the same install runs (another profile, a forwarding launch, a helper). The process check compares image paths under the install folder and skips the own process id; a failed check counts as "another runs".
- **Interrupted downloads.** Velopack writes `.partial` and renames it only after the checksum passes; the next download removes old partial files. A killed download never leaves a package that applies.
- **Elevation.** One UAC prompt, only for an older running service and an installed app, at most once per revision. Never inside a Velopack hook, never for a portable copy, never to replace a newer service with an older one. Known gap, also true today: the elevated install copies `navo.exe` from the per-user install folder, which the user can write; code signing would let the elevated step check the publisher.
- **Privacy.** An automatic check sends one request to `api.github.com` (the release list) and up to ten to `github.com` (the small `releases.win.json` files). A download fetches one package (about 33 MB). GitHub sees the IP address, the time and the `ureq` user agent. The requests carry no user id, no Navo version, no settings and no paths (`GithubSource` ignores Velopack's staged user id). Logs keep versions and error kinds only. Opt-out: Settings → Help → "Check for updates automatically" off; then Navo sends nothing by itself.
- **Disk.** Velopack keeps the staged package in `%LocalAppData%\NavoApp\packages` and removes older ones after an apply.

#### Risks and rollback

- R1 — A stolen GitHub account or token ships a bad build to every installed copy. Only account security prevents it today.
- R2 — Networks that inspect TLS fail the check with the bundled roots. The user sees "Could not reach GitHub"; nothing else breaks.
- R3 — A check hangs (Velopack has no timeout here). The runner gives up after 30 s and ignores a late answer; the stuck thread ends with the process.
- R4 — The first start after an update is a few seconds slower while Velopack applies.
- Rollback: `updates.check` off stops automatic requests. A bad release is fixed by a newer release (no downgrade). A merged atom is reverted with `git revert <sha>`; IX8e alone only turns auto-apply off, which is safe to keep.

- D21a — **Module boundary.** A new crate `navo-clipboard` holds the model, the admit rules, the store, search and the service. Only `navo-app` depends on it. `navo-ui` sees a `ClipboardHooks` trait with its own row types, as `RetainedHooks` does. OS calls live in `navo-shell` as general capabilities (watch, private write, DPAPI, paste back). With `clipboard.enabled = false` the app opens no store, starts no watcher, registers no Win+Alt+V, and the commands are disabled and hidden from Ctrl+K; the data stays on disk. B12 later puts the same pieces behind the module registry without changing `navo-ui` callers.
- D21b — **Own database file (approved by the orchestrator 2026-10-30; differs from D17).** D17 puts user data in `navo.db`. B9 uses `<data>/clipboard.db` instead (Windows `%LOCALAPPDATA%\Navo\clipboard.db`; portable mode: the profile's `data` folder), with its own `user_version` migrations, WAL, `synchronous = NORMAL` and `secure_delete = ON`. Reasons: `navo.db` holds the operations journal; a module that can be switched off and wiped should not share its file, migrations or salvage; "Delete all clipboard data" can remove one file set. Cost: a second SQLite file and connection. Approved: CB2 may start.
- D21c — **What history keeps.** Text (`CF_UNICODETEXT`) and file lists (`CF_HDROP` paths plus copy or cut; paths only, never file contents), the source app (the clipboard owner's exe name, best effort) and the time. Never recorded: copies that carry `ExcludeClipboardContentFromMonitorProcessing` or `Clipboard Viewer Ignore`, or `CanIncludeInClipboardHistory` = 0 (password managers set these; the R12 prototype promises it); Navo's own secret copies (they carry the same formats); empty or whitespace-only text; images and other formats; anything over the caps (Q23). The same text or path list again moves the existing entry to the top (key: SHA-256 of kind and body, `sha2` =0.10.9 as in `navo-fs`). The 500 newest stay (D87); the trim runs in the insert's transaction.
- D21d — **Data safety.** *Never logged:* no clipboard text, path list, title, note, saved body or secret reaches tracing, the diagnostic event ring, crash records or the diagnostic report; logs carry kind, length, count and error kind only; CB19 proves it with a canary. *Clear:* "Clear clipboard history" deletes history rows only (saved items, secrets and notes stay) and then runs `wal_checkpoint(TRUNCATE)`; "Delete all clipboard data" closes the store, removes `clipboard.db`, `-wal` and `-shm`, and starts empty; both ask first and name the counts. *Corrupt:* open runs `quick_check`; a corrupt or unreadable file is renamed `clipboard.db.corrupt-<ms>` with its `-wal` and `-shm`, never deleted; Navo starts with an empty store and the palette shows one line about it. *One writer:* the module's worker thread; the profile lock already allows one Navo per profile. History text is stored unencrypted in the user's profile (Q24); secrets are sealed (D21f).
- D21e — **Threads (SD2).** The `navo-shell` watcher thread reads the clipboard (message-only window, `AddClipboardFormatListener`); a `Busy` clipboard is retried 5 times 20 ms apart, then that change is dropped with a debug line that names no content. Store writes run on the module worker. The UI never touches the OS clipboard or the store for history; it reads an `Arc` snapshot with a revision and drops stale replies.
- D21f — **Secrets (D87).** The body is sealed with DPAPI (`CryptProtectData`, current user, `CRYPTPROTECT_UI_FORBIDDEN`); title and user name stay plain and searchable; no snapshot holds plain text; `reveal` returns a wrapper that zeroes its buffer on drop. Copying writes the private formats of D21c and keeps the clipboard sequence number; after 30 s, or at quit if sooner, Navo empties the clipboard only when the sequence is unchanged. Linux builds show "Secrets need Windows" in Secrets mode and save no secret.
- D21g — **Keys (D87, SQ2).** Ctrl+Shift+V in the global context opens the palette in the window; the editor and multi-rename keep their own Ctrl+Shift+V. There Enter copies, Enter on a path goes to it, Ctrl+V on a file list pastes it into the active pane. Win+Alt+V (`clipboard.summon-key`; changeable; empty turns it off; a taken key shows the Tray section's notice) opens the palette in its own pop-up window over the current app while Navo runs; there Enter pastes into that app and Ctrl+C only copies. The pop-up is made on the first summon and hidden, not closed, afterwards. Win+Alt+N stays the Navo summon. Palette keys follow the prototype (`index.html:736-760`): Tab and Shift+Tab modes, Up and Down, Enter, Ctrl+C, Ctrl+S save from history, Ctrl+N new, F2 edit (on a row) or Manage, Del delete, Alt+R reveal, Alt+U copy user, Esc clears the search, then closes.
- D21h — **Look.** Direction 1 (`index.html:473-516`, actions `:429-445`, empty states `:447-456`); the folder note on top of Notes from direction 2 (`:532-572`); the two-column library of direction 3 (`:573-655`) behind F2 "Manage…". Command-center row parts and theme tokens only; fade only, about 80 ms, none with reduced motion; icons centred on the first text line (D86). Modes show only what the hooks offer: B9a shows All and Recent; B9b adds Saved, Secrets and Notes.

#### CB1 — Model and admit rules

- **Change:** new crate `crates/navo-clipboard` (`Cargo.toml` with `sha2` =0.10.9 and `thiserror`; `src/lib.rs`, `src/model.rs`, `src/admit.rs`). No dependency on `navo-core`, `navo-ui` or `navo-shell`. `Captured`, `Entry { content, source_app: Option<String>, first_ms, last_ms, uses: u32 }`, `Saved { id, kind, title, body: Option<String>, user: Option<String>, scope, created_ms, updated_ms }`, `Limits { max_text_bytes, max_paths, max_entries }` with the Q23 defaults. `admit` trims nothing: it keeps or skips with a `Reason { Empty, TooLarge, TooManyPaths }`. `content_key` is SHA-256 over a kind byte and the UTF-8 text or the paths joined by NUL plus the cut flag.
- **Check:** tests: whitespace-only text skipped; text one byte over the cap skipped, at the cap kept; the same paths with copy and with cut give different keys; equal text gives equal keys.

#### CB2 — History store

- **Change:** `src/store/mod.rs` and `src/store/history.rs`. `ClipStore::open(path)` creates the file, sets WAL, `synchronous = NORMAL`, `secure_delete = ON`, `foreign_keys = ON`, and migrates by `user_version` (V1: `clips (id INTEGER PRIMARY KEY, key BLOB UNIQUE, kind INTEGER, body TEXT, paths TEXT, cut INTEGER, source_app TEXT, first_ms, last_ms, uses)`). A newer `user_version` refuses with `ClipError::TooNew`. `record(entry)` in one transaction: an existing key moves to the top (`last_ms`, `uses + 1`), else inserts; then deletes the oldest rows beyond `max_entries`. `history(limit)` newest first; `delete(id)`; `clear_history()` deletes all rows, then `wal_checkpoint(TRUNCATE)`.
- **Data:** D21b, D21d. Nothing here logs a body.
- **Check:** temp-dir tests: 501 records keep 500 and drop the oldest; a repeat moves to the top and counts uses; a reopened store lists the same rows; a V99 file refuses.

#### CB3 — Store safety

- **Change:** `ClipStore::open` runs `PRAGMA quick_check`; on failure, or when SQLite reports `NotADatabase` or `DatabaseCorrupt`, it renames `clipboard.db`, `-wal` and `-shm` to `clipboard.db.corrupt-<ms>` (and the same suffix for the other two), opens a fresh file and returns `Opened::MovedAside(PathBuf)`. It never deletes a file it did not create in that call. `wipe_all(self, path)` closes the connection, removes the three files and reopens empty. Errors keep the old files.
- **Check:** tests: a file of random bytes is moved aside and a fresh store opens; `wipe_all` leaves no `-wal` or `-shm`; after `clear_history` and after `wipe_all`, a canary string is absent from the bytes of every file in the folder.
- **Stop if:** Windows cannot rename the files while another handle is open in the test; report.

#### CB4 — Search

- **Change:** `src/search.rs`. `Mode { All, Recent, Saved, Secrets, Notes }` with the prototype's filters: Saved excludes secrets and notes. Case-insensitive substring over title and body; for path lists over the joined paths; secrets match title and user name only. `Found` carries byte ranges for highlights. All lists history first, then saved items. Notes mode puts notes whose scope equals the given folder (case-insensitive on Windows-style paths) first.
- **Check:** tests per mode; a secret's body never matches; a folder note sorts first; an empty query returns all in order.

#### CB5 — Service

- **Change:** `src/service/mod.rs` and `src/service/worker.rs`. `ClipService::start(store, limits, sink: Arc<dyn ClipSink>) -> ClipService` owns one thread and a bounded channel (64). Inputs: `captured(Captured)`, `copy(id, How { Copy, Paste })`, `delete(id)`, `clear_history()`, `wipe_all()`, `set_recording(bool)`. Out: `snapshot() -> Arc<Snapshot>` with a `revision: u64` and a `subscribe(Box<dyn Fn(u64) + Send>)` callback. `ClipSink { write_text(&str), write_files(&[PathBuf], cut: bool) }` is the port; the worker calls it, never the UI. While recording is off, captured events are dropped. `stop()` drains the channel and joins with a 2 s limit, as `resident/thread.rs` does.
- **Check:** tests with a fake sink and a temp store: a captured text appears in the next snapshot with a higher revision; a repeat does not add a row; recording off drops captures; `copy` calls the sink once; `stop` returns within 2 s with work queued.

#### CB6 — Clipboard watcher (Windows)

- **Change:** `navo-shell/src/clipboard/watch.rs` (Windows) and a Unix stub that returns `ClipboardError::Unsupported`. `Watcher::start(on_change: Box<dyn Fn(ShellCapture) + Send>) -> Result<Watcher, ClipboardError>` makes a thread with a message-only window (`HWND_MESSAGE`) and `AddClipboardFormatListener`.
