# Git badges: skip the status call for unchanged repositories

Status: revised after plan check 2 (Terra xhigh, 8 points); final revision, hand-verified next · Repo: `navo` · Branch: `git-skip` from `main` · Started: 2026-11-05

## What the user sees (human spec)

- Opening a folder with repositories shows each last badge at once, dimmed. About one second later, a repository proved unchanged turns fresh (normal look) with no `git status`. A changed one gets its new badge after the status, as today.
- Returning to the window after a minute or more rechecks only the repositories that changed.
- Always checked again: the Git menu's Recheck (Alt+G); the pane refresh key (`pane.refresh`, which today never reaches the badges); a Git command Navo ran; an automatic fetch, for that repository only.
- A fresh badge is never older than 5 minutes. After that it dims until the next open, focus regain or Recheck. No Git process runs while the window is idle.
- Checked every time, as today: network and removable drives, Linux, submodules, linked worktrees, repositories behind a link, junction or mounted folder, listings with more than 64 repositories, and the first open after a restart.

Sources: the owner's brief and Q1 answer, plan checks 1–2 with the coordinator's decisions (2026-11-05), the code at `75c34d88`. Paths are under `crates/`.

## What exists today (checked at `75c34d88`)

- **Status.** It runs with `GIT_OPTIONAL_LOCKS=0` (`navo-git/src/cli/process.rs:103`), so it writes nothing in `.git`. `fetched_ms` is the mtime of `FETCH_HEAD`. The markers are in `status/operation.rs:10-17`.
- **Watchers** (`navo-fs/src/watch/`).

- **Volumes.** `drive_class` is keyed by the drive-letter prefix (`io_queue/mod.rs:112-125`). `win_volume::mount_point` (`local/win_volume.rs:36`) calls `GetVolumePathNameW` and is `pub(super)`.

## Shape

- **Appetite:** 2 days of agent runs, 11 atoms. Work not done by then stops and needs a new decision.
- **Non-goals:** proofs that survive a restart; a USN-journal source; skipping off fixed local volumes; one thread for many watches; a saved-badge format change; rechecking while idle.
- **Alternatives that lost:**
  - *Fingerprint only.* Owner Q1: no watch means no skip.
  - *The browser's folder watch.* It sees only direct children.
  - *Counting the debounced events.* They are late and can be collapsed.
  - *A synchronous barrier inside the watcher.* A raw counter plus a 1 s confirm needs no new kernel round-trip.
  - *Ignoring `.git` events.* Status writes nothing there, so every event is real.
  - *Rechecking on expiry.* That is a Git process every 5 minutes per repository; dimming costs nothing.

## Decisions

Final. Workers never reopen them; a worker that finds one wrong stops and reports.

- GS1 — **Raw change counter** (navo-fs).
  - `RawSender` carries `count: Arc<AtomicU64>`. `change`, `overflow` and `failed` add 1 before sending, so the count includes changes the batch later collapses.
  - `Watch::raw_changes(&self) -> u64` reads it with `Acquire`.
  - On Windows, `pub fn volume_mount_point(path: &Path) -> io::Result<PathBuf>` wraps `mount_point`.
- GS2 — **Fingerprint** (navo-git).
  - `Fingerprint(u64)` is FNV-1a 64 over stamps in a fixed order. A stamp is `absent` or `(is_dir, len, mtime_ns)`.
  - Stamped: in `<root>/.git`, `HEAD`, `index`, `FETCH_HEAD`, `config`, `packed-refs`, `info/exclude`, `reftable/tables.list` and every `MARKERS` entry (made `pub(crate)`); the branch ref `HEAD` names; and the two upstream candidates `refs/remotes/<u>` and `refs/heads/<u>`. Each candidate passes `safe_ref`: it must start with `refs/`, with no `..`, no empty component, no `\`, no `:` and no leading `/`.
  - `fingerprint(root, upstream, now) -> Option<Fingerprint>` is `None` when:
    - `.git` is not a plain directory;
    - `.git/commondir`, `.git/modules` or `<root>/.gitmodules` exists;
    - a read fails, or a ref is unsafe;
    - an mtime is later than `now - 2 s`.
  - `HEAD` is read up to 256 bytes.
- GS3 — **Root key and class.**
  - `root_key(path)` is the text with `\` for `/`, ASCII-lowercased on Windows. Watches, proofs, deadlines and forced roots use it.
  - `Probe::root_class(root, listing) -> DriveClass` is `Unknown` when any of these holds:
    - any path component between the listing folder and the root, both ends included, is a symlink or junction (`symlink_metadata().file_type().is_symlink()`);
    - `volume_mount_point(root)` is not the drive-letter root `X:\` of `root`;
    - any read fails.

    Otherwise it is `navo_fs::drive_class` of the listing. Off Windows it is `Unknown`.
- GS4 — **Watches** (`scan_watch.rs`, scanner thread).
  - `arm(root, class)` skips anything but `Ssd` or `Hdd`, and volume roots.
  - It keeps `WATCH_CAP` (64) entries, evicting the least recently armed, and drops evicted or failed watches on a `navo-git-watch-release` thread.
  - Each new watch gets a new `epoch`. `arm` stores `identity(root)`, and an absent identity means the root is not armed.
  - `mark(root) -> Option<Mark { epoch, changes }>` is `Some` only when:
    - the watch `is_live`;
    - the current identity is present and equal to the stored one.

    `changes` is `raw_changes()`. Every event counts, `.git` included.
- GS5 — **Proof.** `Proof { mark, fingerprint, upstream: Option<String>, checked_at }`.
  - `launch` reads `pre_mark` and `pre = fingerprint(root, kept upstream)` before the thread starts; `checked_at` is `Probe::now`.
  - `finish(Ok(status))` reads `post = fingerprint(root, kept upstream)`.
  - A proof exists only when `pre_mark`, `pre` and `post` are `Some`, `pre == post`, and the status upstream equals the kept upstream. A first scan that finds a new upstream earns no proof; the next one can.
  - `Ok` without a proof, or any `Err`, removes the root's `Kept`.
- GS6 — **Kept statuses.** `Proofs` holds `root_key → Kept { proof, status: Arc<RepoStatus> }`.
  - The bounds are 64 entries and 4 MiB (`512 + 128 × dirs.len()` each); the least recently used entry goes first.
  - A reuse projects `listing::project(Ok(&kept.status), bindings, root)`.
- GS7 — **Two-phase verdict** (`scan_skip.rs`, pure).
  - `precheck(&Facts) -> Result<(), Why>` checks, in order:
    1. `Forced` (GS9);
    2. `Truncated`: discovery hit `REPO_CAP`;
    3. `NotFixed`: the class is not `Ssd` or `Hdd`;
    4. `NoProof`;
    5. `Expired`: `now < checked_at`, or `now - checked_at >= MAX_PROOF_AGE` (5 min);
    6. `NoCoverage`: the mark is `None`;
    7. `Watched`: the mark differs from `proof.mark`.
  - `confirm(&Facts, fingerprint fn) -> Verdict` reruns `precheck`, then `Unproved` (the fingerprint is `None`) and `Fingerprint` (it differs). Otherwise it is `Reuse`.
  - Phase 1, in `plan`: when `precheck` passes, the plan publishes the kept projection stale and schedules `Confirm { listing, root }` at `now + CONFIRM_WAIT` (1 s: `WATCH_MAX_DELAY` plus margin). The scanner never blocks.
  - Phase 2, when that deadline is due: if the listing is not current, it drops the confirm. Otherwise `Reuse` publishes the projection fresh, and any other verdict pushes `Status(listing, root)`.
  - A change, overflow or failure inside the window bumps or clears the mark, so it scans.
- GS8 — **Deadlines and expiry.** `Deadlines<T>` (pure, in `scan_skip.rs`) offers `insert(at, T)`, `next() -> Option<Instant>`, `pop_due(now) -> Vec<T>` and `retain(f)`.
  - The scanner holds `Deadlines<Timer>`, with `Timer::{Confirm, Expire { listing, root }}`.
  - Every fresh publish of a root (a scan result or a confirmed reuse) inserts `Expire` at `checked_at + 5 min`; a scan result uses its finish time.
  - When it is due, the root's rows in the current badges are republished with `stale = true`.
  - Due entries are removed. `forget` and replace drop the entries of the old listing.
  - `wait` uses `wait_timeout` until `next()`. With no deadlines it parks, as today.
- GS9 — **Rescan scopes.**
  - `Scope { Changed, All, Repo(PathBuf) }`. `Entry.forced: Forced { all, roots: Vec<String> }` holds root keys.
  - `replace` carries the scope over, `forget` clears it, and `take_forced` returns and clears it for the current listing.
  - Past `REPO_CAP` roots it becomes `all`. A `Repo` path matching no root forces all of them.
  - `GitScan::rescan` and `ScanView::rescan` keep their signatures and mean `All`. The new methods are `GitScan::rescan_changed` and `ScanView::rescan_repo`.
- GS10 — **Callers.**
  - Focus uses `rescan_changed`.
  - `rescan_of(repo)` uses `rescan_repo(parent, os_path(repo))`, falling back to `rescan`.
  - The fetch `Watch::rescan(&ScanRepo)` runs before `attempts.insert(repo.path, now)`.
  - `pane.refresh` calls `git_rescan` for the focused local listing.
  - Navo's own file operations raise watch events.
- GS11 — **Ports.** `Probe` gets four default methods, so existing fakes never skip: `fingerprint` → `None`; `watch_tree(root) -> Option<Box<dyn RepoWatch>>` → `None`; `root_class` → `Unknown`; `identity` → `None`.

  `RepoWatch: Send { fn is_live(&self) -> bool; fn changes(&self) -> u64; }` is implemented for `navo_fs::Watch` with a no-op sink. `SystemProbe` moves to `scan_system.rs`; its Windows overrides use `LocalFs::watch_tree`, GS3 and `native_identity`.

## Risks and rollback

- R1 — **Outside inputs** (global config, `core.excludesFile`, included config, global attributes) are not tracked. A change there shows at most 5 minutes late. Accepted.
- R2 — **A write with a restored mtime** is seen by the raw counter, inside `.git` too, and the fingerprint is a second check. The only gap left is a change while no watch is live, and then there is no proof.
- R3 — **Handles and renames.** The watch opens with `FILE_SHARE_DELETE`. A3b proves that renaming or deleting a watched root's parent works; if it fails, A3b stops and the plan returns to the owner.
- R4 — **Threads.** At most 128 parked threads.
- R5 — **No gain.** A tool or engine that writes `.git` during status (gix, if it does) gets no proof, so the repository is scanned as today. The VM check records it.
- R6 — **Dimming after 5 minutes** also applies to badges from a real scan. That is a visible change from today. Coordinator decision.
- Rollback: `git revert <sha>` per atom. No stored data changes.

## Proposed decision entry (for `docs/decisions.md` after the owner accepts)

| D110 | 2026-11-05 | **Git badges skip unchanged repositories.** On a fixed local drive, Navo runs `git status` only when a repository may have changed. It knows one has not changed when its subtree watch counted no raw change and its `.git` fingerprint is unchanged, both confirmed one second after the folder opens, and its last real check is under 5 minutes old. Until then the last badge shows dimmed. Recheck, the refresh key, Git commands and a fetch always check again. Any fresh badge dims after 5 minutes, with no Git process while idle. These are checked every time: network and removable drives, Linux, submodules, linked worktrees, linked or mounted roots, listings over 64 repositories, and the first open after a restart. Global Git configuration changes show at most 5 minutes late. | Proposed |
