## Decisions

Workers implement these contracts; they stop if evidence contradicts one. Sol means `gpt-6.1-sol`. Explicit Qwen 4 Max dispatch follows this brief even though the current role pool lists older defaults; the orchestrator must select that model, not silently substitute one. Owner-approved direction is distinguished from implementation choices.

- **TP1 — Accepted, owner direction: two passes.** Supersedes RD6 for full builds. Pass 1 restarts MFT enumeration at cursor 0, retains only directory identities, parent identities, names and flags, and counts file/name capacities without keeping file records. Resolve the directory graph and insert directories in parent-before-child order. Pass 2 restarts at cursor 0 and streams files directly into their already-present parents. “Parent order” means every parent precedes its files; do not sort or spool millions of files. Consequence: two complete `FSCTL_ENUM_USN_DATA` traversals, with bounded buffers and folder-only scratch, replace the full-build blocked queue.
- **TP2 — Accepted implementation choice: keep MQ2 for journal batches.** `BatchApply` still needs `Pending` for out-of-order Add/Rename and their later Size/Remove changes. Keep `pending.rs`, its compact storage and ordering tests. Full builds never construct `Pending`; `Enumeration.blocked_peak` remains for compatibility and is 0 there. Move the queue-storage assertion out of the full-build peak expectation; retain the ≤48 B/record queue guard.
- **TP3 — Superseded by TP9; historical one-journal-window choice.** Capture journal ID and start USN before pass 1; retain that cursor until post-build catch-up. Validate continuity between passes and after pass 2. Size I/O happens only for files in pass 2, once per file, with today's FileGone/unknown-size rules. Missing parents, cycles, conflicting directory identities and files whose parent appeared only after pass 1 return `Reenumerate`, never a silently partial promoted index. Bounded retries use the existing rebuild window; old search remains available. Journal replay from the original cursor resolves changes during both reads before promotion. No unlimited retry loop or per-file orphan queue.
- **TP4 — Accepted, owner direction: search-only old generation.** Supersedes RD1's requirement to keep the old index whole. Under the existing shared write lock, release old children, file bytes, folder counts, FRN map and pending renames; retain names, offsets, parents, flags and scalar metadata. Do not clone, compact, shrink or rebuild retained columns. `NtfsIndex` has an explicit private search-only flag; its table is read-only by contract. Search, filters, paths, flags and entry counts work as before; snapshot and batch APIs reject this mode. Capture the small `SizeHint` before conversion. Only the replacement can restore totals.
- **TP5 — Superseded by TP10; historical quarantine mechanism (owner preservation direction retained).** Keep the canonical v3 snapshot in place and quarantine it logically with an atomic `<snapshot>.rebuilding` marker; no eager unlink or rename. The marker holds version, volume serial and saved journal position. Missing marker means normal startup; present, torn or unrecognised marker means search-only recovery, never journal resume or ordinary save from that snapshot. First establish a recoverable checkpoint using `file::save_with_ids` and its existing streamed atomic writer/backup, then persist the marker, then degrade memory. If no checkpoint exists and `snapshot()` is unavailable because a rename is pending, stop before conversion and keep the full index searchable. This safety failure is reported, never counted as a successful memory run. A cold first build with no prior generation/checkpoint uses the same two-pass builder without a recovery checkpoint; these preservation guarantees apply to a rebuild with an existing generation.
- **TP6 — Superseded by TP10; historical promotion sequence.** Acquire the global permit before checkpoint work or conversion; queued volumes keep their full generation. Build privately, catch up from TP3's cursor to a captured journal high-water mark, require an available snapshot with no pending rename, check cancellation, and durably save the complete candidate before replacing the shared generation. Swap under the write lock, drop the old generation, trim the new table, then clear the marker and release the permit. Do not observe cancellation inside the short durable-save/swap commit sequence. Save/flush failure keeps the marker, prior snapshot/backup and old search; retry never reloads a full snapshot over an existing search-only generation. Shutdown skips saving search-only state. On restart, recover one valid v3 canonical/backup generation once, publish it for search and rebuild; mismatched volume serials are never published. A stale journal permits search-only recovery, not replay. A crash after save but before swap safely rebuilds the saved candidate.
- **TP7 — Superseded by TP11; historical Busy mapping (owner waiting direction retained).** For a requested rebuilding volume, totals replies contain `None` at its positions and `busy=true`; do not consult released child lists. Existing healthy-volume totals remain positional. Add a client method returning the existing `FolderTotalsReply`; preserve the legacy method. At the app boundary use `TotalsState::{Ready(FolderTotals), Busy, Unavailable}`. Busy shows the existing waiting indicator and an unknown value, never 0, stale counts, or “complete”; it does not start a replacement recursive measurement. Unavailable keeps today's fallback, including D103 limits. Ctrl+K shows old hits and the existing rebuild status. Visible totals retry at most once per second through cancellable background jobs, stop on navigation/Esc, and show new totals within two seconds of promotion. Do not add a new wire version or screen.
- **TP8 — Superseded by TP12; historical proof scope.** Linux static-volume full rebuilds at 3 M and 5 M must be ≤1.7× the old full resting allocation; first builds remain ≤1.7× final resting allocation. Include conversion, staging, both reads, catch-up, streamed save, swap and trim. VM median end-to-end build duration must be ≤110% of MQ2-enabled main, separately for cold and warm runs at both sizes. Linux fixtures also report per-pass enumeration calls/bytes, pass times and size-read count. The VM reports total build time and peak private bytes. A second traversal repeats kernel enumeration and name decoding even when cached; file-size queries must not double. Do not assume twice the I/O means twice the elapsed time. Stop on either failed gate; no owner-approved relaxation is implied.

- **TP9 — Accepted; supersedes TP3: continuity and one selected name per FRN.** Keep the start journal ID/USN across both cursor-zero traversals and replay through a captured high-water USN before promotion. Validate continuity between passes and afterward. Keep the existing single-FRN enumeration policy: one selected enumerated name/parent per FRN, not all hard links. Any journal record with `HARD_LINK_CHANGE` (`0x10000`), including combined reasons, returns `Reenumerate` immediately after `parse_batch`, before `refresh_sizes`, cursor validation or `into_changes`; never accept its current attributes-only mapping. This can defer completion under link churn. Apply creates, deletes, paired renames and directory moves through MQ2; reject unresolved results even though `BatchApply::finish` advanced the cursor. Size reads occur only for pass-2 files, once per file except the existing malformed-record fallback; FileGone/unknown-size rules remain. Missing/new parents, cycles or conflicting directory identities fail the candidate. Root reference aliases retain their sequence normalization. Retry stays bounded by the existing rebuild window; old search remains available.
- **TP10 — Accepted; supersedes TP5/TP6: quarantine before checkpoint, then durable promotion.** Acquire the global permit; queued volumes keep the full generation. Validate that at least one matching canonical/backup v3 snapshot is recoverable, or that a full in-memory snapshot can establish one. Persist and durably acknowledge `<snapshot>.rebuilding` BEFORE any checkpoint replacement, including a structurally valid checkpoint whose cursor advanced over unresolved changes. A crash at that next instruction must recover search-only, never resume its journal. Active marker contains version/serial/cursor; present, torn or unknown means no replay and no ordinary save. If neither existing disk copy nor `snapshot()` is usable, retain full memory and stop before conversion. A cold build without an old generation needs no recovery checkpoint.
  S4 adds `native_replace_durable(source, target) -> io::Result<()>`: synced same-volume temporary file, strict write-through replacement without plain-rename fallback, then a flush of the actual snapshot-storage volume on Windows; Unix syncs the parent. Permission, unsupported-volume, replace or flush failure stops conversion. S14 must prove this on Windows before T8 activates it. This adds latency and needs LocalSystem volume access. The Windows barrier follows [Microsoft's volume flush contract](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers); it does not treat today's no-op directory sync as durable.
  If recovery chose `.bak` because canonical is corrupt, copy the validated backup through a bounded buffer to a new repair sibling, sync it and strictly replace canonical; leave `.bak` byte-for-byte intact until canonical repair is durable. Never call the ordinary canonical writer in that state: it makes `.bak` from canonical before replacement. Load only one valid old generation; repair copies bytes rather than loading another table. Checkpoint/candidate writes use `file::save_with_ids` to fresh same-directory staging paths, then strict durable replacement; backup preparation uses validated copies only. Preserve the last validated copy through every error and ambiguous post-replace result.
  Capture SizeHint, convert with `Arc::get_mut` under the write lock, and build privately without shared locks. Catch up to high-water; require no unresolved changes or pending rename. Check cancellation before commit. Durably save the complete candidate, swap, drop old, trim, then durably clear the marker and release the permit. Clearing uses a small versioned complete record through S4, followed by unlink; an absent marker permits ordinary validation; a complete record permits resume only when its serial/journal/cursor/checksum matches the durable canonical snapshot, while an old active/torn marker safely forces another rebuild. Ignore cancellation within this commit sequence. Failed save/cleanup retains old search or the promoted generation plus quarantine; retry never reloads a full old snapshot, and shutdown skips search-only saves. Recovery checks serials and loads once; stale journals permit search-only recovery. Backup recovery is ALWAYS quarantined unless replay safety is independently established for that exact backup identity. A valid checksum, journal continuity, canonical promotion or absent/complete marker cannot establish this: a checkpoint cursor may have skipped unresolved changes. This plan supplies no independent backup replay-safety proof, so every backup load publishes search-only, persists active quarantine before repair, and rebuilds. Repair never upgrades its safety. Complete-marker permission applies only to its matching canonical. No snapshot-format change.
- **TP11 — Accepted; supersedes TP7: rebuild Busy and deadline failure differ.** Reserve existing `FolderTotalsReply.busy=true` for positively identified requested search-only volumes. Return None only at those positions, preserving healthy positional totals. Any service deadline expiry, lock timeout or expired lookup invalidates the whole request as `{ totals: vec![None; paths.len()], busy: false }`, even after partial work; timeout takes precedence over Busy. This loses partial totals on timeout but cannot create indefinite waiting. Client validates count/generation and returns the existing reply; legacy decoder still rejects busy. The app queries one local path, maps Some to Ready, `None && busy` to Busy, and `None && !busy`/errors to Unavailable. Unavailable retains existing fallback/D103 limits. Busy retains existing waiting/unknown cues without recursive measurement; cancellable background retry runs at most once per second and refreshes within two seconds of promotion. No wire revision, network change or new screen.
- **TP12 — Accepted; supersedes TP8: measure both first builds and rebuilds.** At EACH of 3 M and 5 M files, deep out-of-order first build peak/final resting allocation and full rebuild peak/full-old resting allocation must independently be ≤1.7. Rebuild includes quarantine/checkpoint work, conversion, graph staging, both reads, query load, catch-up, streamed save, swap, old drop and trim. S8 runs four named numerical assertions, with recorded assertion failures before fixes; ordered alternatives and inferred ratios are not gates. Keep D109 fallback/growth limits and MQ2 queue tests separate. VM medians stay ≤1.10× MQ2-enabled main separately for three cold and five warm trials per size, using complete trigger-to-ready time. Report actual denominator bytes, raw bytes/MiB, pass calls/bytes/times and file-size reads. Stop on either memory or time failure; no relaxation is implied.

## Risks and rollback

- R1 — Directory churn between reads can invalidate the parent set. TP3 rejects that candidate and retains old search. Sustained churn or journal wrap can prevent completion; expose the existing update error and defer retry.
- R2 — An `Arc` clone could retain the full old generation or cause copy-on-write. Conversion uses `Arc::get_mut` only; on failure keep search, defer and report the holder. Never use `Arc::make_mut` to degrade. Test the held-reader path and release all published clones before conversion.
- R3 — Replacement can commit before a flush fails. TP10 retains quarantine and a validated disk copy; S4 supplies the missing strict durability primitive, while streamed v3 encoding remains unchanged. Backup-only recovery must repair canonical before backup rotation.
- R4 — Process allocator retention and search scratch can exceed Linux allocation measurements. The VM measures the actual service, including repeated Ctrl+K queries, checkpoint writes and cancellation. No Linux result substitutes for Windows evidence.
- R5 — Busy propagation changes three UI boundaries. A timeout must remain Unavailable, not indefinitely Busy. Preserve network behaviour and reject stale replies using existing owner/load IDs.
- **Rollback:** stop the isolated service; preserve canonical snapshot, `.bak` and `.rebuilding` together in a dated backup directory. Restore the last complete v3 checkpoint with `Copy-Item -LiteralPath <backup> -Destination <snapshot>` while stopped; start the MQ2 baseline binary, which checks volume/journal validity and rebuilds if required. Never deploy that older binary over a live quarantine without this recovery step. No rollback/deploy runs are authorised by this planning task.

**Session contract (new, S9–S12):** `PreparedRebuild<'a>` owns `BuildPermit<'a>`, `SizeHint`, snapshot paths and the validated recovery source (canonical or backup, serial, journal cursor and stored checksum); the worker owns Shared and cancellation. `prepare(shared: &Shared, path: &Path, drive: Drive, cancel: &CancelToken) -> Result<PreparedRebuild<'static>, NtfsError>` performs the TP10 pre-conversion sequence. `commit(self, shared: &Shared, candidate: NtfsIndex, high_water: JournalPosition, cancel: &CancelToken) -> Result<(), NtfsError>` consumes the permit only after durable promotion/cleanup or a failed attempt retaining quarantine. Windows I/O remains in worker callbacks: journal read accepts JournalPosition and returns UsnBatch, enumerate accepts SizeHint/CancelToken and returns Enumeration. Catch-up is driven before commit using these callbacks; its result is rejected on nonempty unresolved changes even if finish advanced the cursor; commit rejects a position short of high_water, unresolved finish or pending rename. Shared never contains two published generations. S9/S10 extract only existing save/hint/swap functions; S11/S12 add these dormant types/methods.
