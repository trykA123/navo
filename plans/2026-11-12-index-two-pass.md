## Goal

During a full rebuild, Ctrl+K searches the previous generation while the replacement builds within 1.7× the resting index allocation at both 3 M and 5 M files. Folder totals and sizes stay visibly busy until promotion. Cancellation, retry and restart preserve a searchable generation and every recoverable snapshot.

The checker worktree's `checker-{1,3,5}m.log` and `crates/navo-index/src/ntfs/checker_peak_probe.rs:1-250` show four-deep trees, 10% folders and 30% early files. ## Decisions

Workers implement these contracts; they stop if evidence contradicts one. Sol means `gpt-6.1-sol`. Explicit Qwen 4 Max dispatch follows this brief even though the current role pool lists older defaults; the orchestrator must select that model, not silently substitute one. Owner-approved direction is distinguished from implementation choices.

- **TP1 — Accepted, owner direction: two passes.** Supersedes RD6 for full builds. Pass 1 restarts MFT enumeration at cursor 0, retains only directory identities, parent identities, names and flags, and counts file/name capacities without keeping file records. Resolve the directory graph and insert directories in parent-before-child order. Pass 2 restarts at cursor 0 and streams files directly into their already-present parents. “Parent order” means every parent precedes its files; do not sort or spool millions of files. Consequence: two complete `FSCTL_ENUM_USN_DATA` traversals, with bounded buffers and folder-only scratch, replace the full-build blocked queue.
- **TP2 — Accepted implementation choice: keep MQ2 for journal batches.** `BatchApply` still needs `Pending` for out-of-order Add/Rename and their later Size/Remove changes. Keep `pending.rs`, its compact storage and ordering tests. Full builds never construct `Pending`; `Enumeration.blocked_peak` remains for compatibility and is 0 there. Move the queue-storage assertion out of the full-build peak expectation; retain the ≤48 B/record queue guard.
- **TP3 — Accepted implementation choice: one journal window.** Capture journal ID and start USN before pass 1; retain that cursor until post-build catch-up. Validate continuity between passes and after pass 2. Size I/O happens only for files in pass 2, once per file, with today's FileGone/unknown-size rules. Missing parents, cycles, conflicting directory identities and files whose parent appeared only after pass 1 return `Reenumerate`, never a silently partial promoted index. Bounded retries use the existing rebuild window; old search remains available. Journal replay from the original cursor resolves changes during both reads before promotion. No unlimited retry loop or per-file orphan queue.
- **TP4 — Accepted, owner direction: search-only old generation.** Supersedes RD1's requirement to keep the old index whole. Under the existing shared write lock, release old children, file bytes, folder counts, FRN map and pending renames; retain names, offsets, parents, flags and scalar metadata. Do not clone, compact, shrink or rebuild retained columns. `NtfsIndex` has an explicit private search-only flag; its table is read-only by contract. Search, filters, paths, flags and entry counts work as before; snapshot and batch APIs reject this mode. Capture the small `SizeHint` before conversion. Only the replacement can restore totals.
- **TP5 — Accepted, owner direction; mechanism chosen here: durable quarantine.** Keep the canonical v3 snapshot in place and quarantine it logically with an atomic `<snapshot>.rebuilding` marker; no eager unlink or rename. The marker holds version, volume serial and saved journal position. Missing marker means normal startup; present, torn or unrecognised marker means search-only recovery, never journal resume or ordinary save from that snapshot. First establish a recoverable checkpoint using `file::save_with_ids` and its existing streamed atomic writer/backup, then persist the marker, then degrade memory. If no checkpoint exists and `snapshot()` is unavailable because a rename is pending, stop before conversion and keep the full index searchable. This safety failure is reported, never counted as a successful memory run. A cold first build with no prior generation/checkpoint uses the same two-pass builder without a recovery checkpoint; these preservation guarantees apply to a rebuild with an existing generation.
- **TP6 — Accepted implementation choice: promotion is the commit point.** Acquire the global permit before checkpoint work or conversion; queued volumes keep their full generation. Build privately, catch up from TP3's cursor to a captured journal high-water mark, require an available snapshot with no pending rename, check cancellation, and durably save the complete candidate before replacing the shared generation. Swap under the write lock, drop the old generation, trim the new table, then clear the marker and release the permit. Do not observe cancellation inside the short durable-save/swap commit sequence. Save/flush failure keeps the marker, prior snapshot/backup and old search; retry never reloads a full snapshot over an existing search-only generation. Shutdown skips saving search-only state. On restart, recover one valid v3 canonical/backup generation once, publish it for search and rebuild; mismatched volume serials are never published. A stale journal permits search-only recovery, not replay. A crash after save but before swap safely rebuilds the saved candidate.
- **TP7 — Accepted, owner direction; UI contract chosen here: busy is distinct from absence.** For a requested rebuilding volume, totals replies contain `None` at its positions and `busy=true`; do not consult released child lists. Existing healthy-volume totals remain positional. Add a client method returning the existing `FolderTotalsReply`; preserve the legacy method. At the app boundary use `TotalsState::{Ready(FolderTotals), Busy, Unavailable}`. Busy shows the existing waiting indicator and an unknown value, never 0, stale counts, or “complete”; it does not start a replacement recursive measurement. Unavailable keeps today's fallback, including D103 limits. Ctrl+K shows old hits and the existing rebuild status. Visible totals retry at most once per second through cancellable background jobs, stop on navigation/Esc, and show new totals within two seconds of promotion. Do not add a new wire version or screen.
- **TP8 — Accepted implementation stop rule: memory and time both gate.** Linux static-volume full rebuilds at 3 M and 5 M must be ≤1.7× the old full resting allocation; first builds remain ≤1.7× final resting allocation. Include conversion, staging, both reads, catch-up, streamed save, swap and trim. VM median end-to-end build duration must be ≤110% of MQ2-enabled main, separately for cold and warm runs at both sizes. Linux fixtures also report per-pass enumeration calls/bytes, pass times and size-read count. The VM reports total build time and peak private bytes. A second traversal repeats kernel enumeration and name decoding even when cached; file-size queries must not double. Do not assume twice the I/O means twice the elapsed time. Stop on either failed gate; no owner-approved relaxation is implied.

## Risks and rollback

- R1 — Directory churn between reads can invalidate the parent set. TP3 rejects that candidate and retains old search. Sustained churn or journal wrap can prevent completion; expose the existing update error and defer retry.
- R2 — An `Arc` clone could retain the full old generation or cause copy-on-write. Conversion uses `Arc::get_mut` only; on failure keep search, defer and report the holder. Never use `Arc::make_mut` to degrade. Test the held-reader path and release all published clones before conversion.
- R3 — Snapshot write failure can occur after replacement committed. Treat any ambiguous error as quarantined; preserve the existing `.bak`, validate checksum/identity at recovery, and never delete the last good generation. Reuse `navo_store::write_atomic_streamed`; no new atomic-write implementation or snapshot format.
- R4 — Process allocator retention and search scratch can exceed Linux allocation measurements. The VM measures the actual service, including repeated Ctrl+K queries, checkpoint writes and cancellation. No Linux result substitutes for Windows evidence.
- R5 — Busy propagation changes three UI boundaries. A timeout must remain Unavailable, not indefinitely Busy. Preserve network behaviour and reject stale replies using existing owner/load IDs.
- **Rollback:** stop the isolated service; preserve canonical snapshot, `.bak` and `.rebuilding` together in a dated backup directory. Restore the last complete v3 checkpoint with `Copy-Item -LiteralPath <backup> -Destination <snapshot>` while stopped; start the MQ2 baseline binary, which checks volume/journal validity and rebuilds if required. Never deploy that older binary over a live quarantine without this recovery step. No rollback/deploy runs are authorised by this planning task.
