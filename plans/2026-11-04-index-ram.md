# Index RAM: cut the peaks of the index service and the walker

Status: ready for plan check 3 (check 2: five must, two should closed) · Repo: `navo` · Branch: `index-ram` from `main` · Started: 2026-11-04

## Goal

The index needs less extra memory while it rebuilds, compacts, loads or grows. Search keeps answering during a rebuild (D83). Each saving is proved by a counting-allocator test that fails first, and a guard test keeps it.

Sources: the two RAM audits of 2026-11-04, plan checks 1–2, D11, D83, D103. Where they disagree, the code at `291ff143` decided. Scale: the local PC has 2.6 M files; 5 M is the scale gate. Plan decisions are `RD1`–`RD12`; `D11`, `D83`, `D103` are project decisions in `docs/decisions.md`.

## What exists today (checked at `291ff143`, paths under `crates/`)

- **Rebuild.** `navo-index-service/src/worker.rs:116-125` builds a new index while the old `Arc<NtfsIndex>` answers; `replace` (`:218`) swaps them. `build` (`:159-200`) resets the save clock, discards the snapshot, then enumerates on the worker thread, so a volume neither follows nor saves while it builds. `enumerate_volume` (`navo-index/src/ntfs/volume_io.rs:54`) starts from an empty table and map, grows by doubling, then `shrink_to_fit` (`:91`). `mft_records()` counts used and free MFT slots (`volume_io.rs:222`). One worker per volume (`runtime.rs:56`); nothing serialises builds. Measured at 1.1 M: build peak 132.9 MiB for an 84.4 MiB index.
- **Compaction** (`navo-index/src/table/mod.rs:266-307`): `Vec<Option<u32>>` remap (8 B/slot), a fresh table that reserves the whole old name arena, fresh child arrays (`children.rs:38`), a trim while the old table lives, then `FrnMap::remap` shrinks while the remap lives (`usn/frn_map.rs:82`). Trigger: `slots >= 100_000 && slots > 2 * len` (`ntfs/compact.rs:10`).
- **MFT dependency queue.** `Pending` (`ntfs/mod.rs:197-290`) keeps records whose parent is unseen, unbounded and uncounted.
- **Load** (`file.rs:105`) reads per-slot counts (format), then `restore_totals` (`table/totals.rs:106`) and `rebuild_totals` (`:123`) add `remaining: Vec<usize>` (8 B/slot) and `ready: Vec<u32>`. Measured: +21.3 MiB at 1 M. `rebuild_totals` is called only from `restore_totals`, after `valid_structure` and `relink`.
- **Growth after an exact fit.** Load and build end at exact capacity; the next `push` (`table/mod.rs:195`) doubles every column.
- **Copy-on-write.** `batch.rs:61` uses `Arc::make_mut`; a held reader copies the whole index (ignored test `batch_tests.rs:181`). No production reader holds an `Arc` across a batch.
- **Walker.** `host/scan.rs:59-86` keeps the walked table alive through `merge_subtree` (`:87-118`), which appends and marks dead, never compacts. An `EntryLimit` outcome returns before the swap, so the old table stays.
- **Network roots.** With `search.network = true` and no chosen roots, `roots.rs:47-63` walks whole network drives, with `max_entries: u32::MAX` (`search_hooks/index.rs:298`). D103 forbids that.
- **Measurement.** `navo-index/src/heap_probe.rs`: `Probe::start` sets the baseline to the live heap; `peak` and `retained` are relative to it; a moving `realloc` counts old + new. `ntfs/memory_tests.rs` has budgets on retained bytes and one load peak.

## Shape

- **Appetite:** two days of agent runs, 18 atoms. Work not done by then stops and needs a new decision.
- **Non-goals:** the steady layout (Q2); freeing the old index during a rebuild (cut, RD1); sizing first builds from the MFT count; search scratch; the pipe job queue and the app metadata cache; a dead-name-bytes trigger; compaction after watcher patches in the host; walker frontier and backlog bounds; the walker time cap (D103 plan); any snapshot format change.
- **Alternatives that lost:** an answer-only old index during rebuild (failure, cancel and retry handling in Windows-only code; check 1 findings 1–2); in-place compaction (fragile link moves; finding 5); MFT-sized first builds (free slots overestimate; finding 4); a segmented or disk-backed index (over the appetite); removing `Arc` generations (readers' ids would change).

## Decisions

Final. Workers never reopen them; a worker that finds one wrong stops and reports.

- RD1 — **Rebuild keeps the old index whole.** Supersedes draft D1 (answer-only index); atoms R2a and R2b are cut. Good: no new lifecycle states, save and follow paths stay as today. Bad: rebuild peak ≈ old + new ≈ 2.1× steady (target ≤ 2.2×), not 1.6×.
- RD2 — **Pre-size rebuilds from the old index only.** `SizeHint { entries, folders, name_bytes, references }` are **total** capacities; `Default` (all 0) reserves nothing. `hint_from_counts(len, folders, live_name_bytes, references)` (pure): `entries = len + len / 16`, `folders = folders + folders / 16` (capped at `entries`; `counts` holds folders only), `name_bytes = live + live / 16` (live names only; dead names in the old arena never count), `references` unchanged (no extra: `+1/16` can cross a hash bucket class and double the map); `saturating_add`, then caps `entries <= u32::MAX as usize - 1`, `name_bytes <= u32::MAX as usize`, `references <= entries`. First builds use the default. The new index already holds the root, so each reserve asks only for `total.saturating_sub(current)`: `NameTable::try_reserve_total(entries, folders, name_bytes)` (`counts` to `folders`, every other column to `entries`, and the arena) and `FrnMap::try_reserve(references.saturating_sub(ids.len()))`. Any failure logs a warning and the build restarts from `NtfsIndex::new`, keeping no partial reserve. The end-of-build trim shrinks a column only when its spare capacity exceeds `len / 16`.
- RD3 — **Grow by an eighth.** Columns: `grow_column<T>(&mut Vec<T>)` reserves `max(len / 8, 1_024)` exactly when `len == capacity`. Name arena: `grow_names(names: &mut String, needed: usize)` reserves `max(len / 8, 16 * 1024, needed)` exactly when `capacity - len < needed`. Bad: more small copies when building from zero; timing must stay within 10 %.
- RD4 — **One build at a time** per service process. `BuildPermit<'static>` from a static `Permits { busy: Mutex<bool>, freed: Condvar }`; `acquire(cancel)` waits in 100 ms slices and returns `Err(NtfsError::Cancelled)` once `cancel.is_cancelled()`; `Drop` clears `busy` and notifies. `build` takes it right after `discard_snapshot` and returns it: `Result<(NtfsIndex, BuildPermit<'static>), NtfsError>`. `rebuild` drops it after `replace`; `open` stores it in a local `Option` from inside the `restore_or_enumerate` closure and drops it after `replace`. Errors and cancels drop it at once (RAII). A waiting volume behaves as a building one today: old index answers, progress 0, no follow, no save. Loads are not gated. Owner accepted (Q3).
- RD5 — **Compaction column by column.** Supersedes draft D5 (in place). `pub struct Remap(Vec<Option<NonZeroU32>>)` stores `new + 1` (4 B/slot, no id reserved as a sentinel); `get(old) -> Option<u32>` is `None` for removed and out-of-range ids. Every step filters old ids by `remap.get(id).is_some()`, never by flags. Order: names + offsets into `String::with_capacity(live_name_bytes)` and an exact `Vec`, then flags, bytes, parents (`remap.get(p).unwrap_or(NO_PARENT)`), each assigned at once so the old column drops; `counts` via `retain_mut` in place; children through `Children::remapped` (same filtering of removed children, sibling order, waiting children become `NO_PARENT`, `relink()` fallback), whose link walk C1b bounds: at most `first.len()` links in total and every child id `< first.len()`, else `None`. The file-reference map is remapped in place and shrunk after the `Remap` drops. Output equals today's algorithm (oracle).
- RD6 — **MFT queue: measure first.** No cap that drops records. The build logs `blocked_peak`; MQ2 runs only if a real volume logs more than 1 % of its entries.
- RD7 — **Load totals without scratch.** Post-order walk from id 0 over `first_child`, `next_sibling` and parent links; at most `2 * slots + 2` steps. `slots == 0`, or a deleted root with `len == 0`, returns `true` at once. Exceeding the bound or visiting a number of live entries other than `len` returns `false`, so the snapshot is rejected (one rebuild). Format, checksum, `valid_structure` and the stored-totals comparison stay unchanged; `file.rs` and `ntfs/snapshot.rs` are not edited; a golden-bytes test (L0) proves format v3 saves and loads as on `main`.
- RD8 — **Copy-on-write guard.** Generations stay. The ignored test becomes a passing one; `with_index` warns with the index size whenever `Arc::get_mut` fails.
- RD9 — **Walker.** After a successful subtree merge the walked table is dropped, then the host compacts under the same write lock when `slots >= COMPACT_MIN_SLOTS && slots > 2 * len`. Accepted pause: one O(slots) compaction per doubling of dead slots, as NTFS does; the longest read-lock wait during a 1 M-slot refresh is ≤ 250 ms on the VM, and the refresh peak is ≤ table before + 2 × walked + 48 B per live entry (amended from 40 after W2 measured +1.9 %). Network drive roots are walked only when listed; every network root gets `max_entries = navo_fs::NETWORK_WALK_MAX_ENTRIES` (D103); over it, "index entry limit reached" shows and the old table stays.
- RD10 — **Peak scenarios** (`ntfs/peak_tests.rs`, all relative to `Probe::start`). `build`: probe before `MftFixture::read` (1.1 M); transient = `peak - held(index)`, per entry. `compact`: 1 M slots (root + files, file reference = id + 100), remove odd ids and id 2 through `table.remove` + `ids.remove`, assert `slots > 2 * len`; probe after; assert `compact_if_sparse(COMPACT_MIN_SLOTS)` is true and `slots == len`; incremental peak per live entry. `load` (1 M files) and `load_folders` (1 M, every 4th entry a folder, files under folders): probe before `load_with_ids` + `restore`; transient per entry. `push_after_load`: probe after load; one `push` under the root; incremental peak per entry, no index term. Each line prints `RAM <case>: peak <KiB>, retained <KiB>, per-entry <B>`.
- RD11 — **Check form.** `flock ~/.cache/rusty-cargo.lock nice -n 10 env CARGO_BUILD_JOBS=8 CARGO_TARGET_DIR=<wt>/target cargo nextest run -p <crate> <filter> > <wt>/../<atom>.log 2>&1; echo $?`, then the same prefix with `cargo xtask check -p <crate> >> <wt>/../<atom>.log 2>&1; echo $?`, then `tail -n 40` of the log. Pass = both exit 0.
- RD12 — **Windows-only code** (`worker.rs`, `ntfs/windows.rs`) is not compiled on Linux: logic goes into Linux-tested files, these get call lines only. The orchestrator runs `windows-quick.yml` on the branch after R1a, R1b and P1. VM CI proves compile and tests, not peaks; peaks come from the VM check in Done when.

## Risks and rollback

- R1 — Compaction or the totals walk corrupts the index. Prevented: oracle tests against today's algorithms on seeded random tables; existing compaction and totals tests unchanged; `senior`; `reviewer-senior` on the branch.
- R2 — A permit is never released or a cancel hangs. Prevented: RAII drop, poison-tolerant locks, 100 ms wait slices, tests for drop, panic and cancel.
- R3 — Network caps hide files. Accepted by D103; the limit message shows.
- R4 — Linux probe numbers differ from Windows private bytes (allocator retention). Separate VM measurement (Done when).
- No user file is written; the index is derived data. Rollback: `git revert <sha>`; a bad snapshot is fixed by deleting `%ProgramData%\Navo\index\<letter>.index`, then the service rebuilds.
